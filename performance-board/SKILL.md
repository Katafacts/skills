# Performance board

A Plan vs. Actual matrix for the vital few key performance indicators (KPIs) that matter to a function, period by period, computed red or green from real numbers, not asserted — where every red gets containment and a note on what's being done, closing the loop into an abnormality/root-cause log and a countermeasure register.

Family: Daily management · Format: .xlsx · Domain: core

## What it is

A performance board tracks the vital few key performance indicators (KPIs) that matter to a function — a Plan and an Actual for each, period by period — and computes each period's status directly from the numbers: green if the actual meets or beats plan, red if it misses. Every red gets a response, not just a color: containment (a quick action that protects the customer or the next process now) and a short note on the board saying what's being done and who owns it. Log it in the abnormality log too (a cause seen first-hand at the gemba — the place the work happens — never speculation) and open a countermeasure with a real owner and a target date. The board also flags a KPI that has missed two or more periods running. Treat that as a prompt to check whether containment is holding, not as a test of whether the miss is a real change or ordinary ups and downs: two points in a row can't tell you that. To judge whether performance is genuinely shifting, plot the KPI on a run chart (its values in time order around a centre line) and look for a sustained pattern over enough points, such as a long run on one side of the median. Sources: David Mann, Creating a Lean Culture (daily management and visual boards); Perla, Provost and Murray, "The run chart: a simple analytical tool for learning from variation in healthcare processes", British Medical Journal (BMJ) Quality & Safety (2011).

## When to use it

Use it when:

- A function already has (or can name) a small set of KPIs with real plans, and wants an honest, computed record of how each one is actually tracking, not a subjective status update.
- You want every miss to trigger a real response — containment now, a note on what's being done, and root-cause work where it's needed — with a closed loop back to a countermeasure and a verification step, not just a color that gets glanced at and forgotten.
- You review the same KPIs on a regular cadence and want the history kept, so trends can be judged on a run chart rather than argued about from memory.

Not when:

- You don't have a real plan or target for the KPI yet, just a hope it goes the right direction — set a real plan first, or every period will just read as an ungrounded pass/fail.
- The KPI genuinely doesn't have periodic data behind it (it's a one-time measurement, not a recurring one) — a performance board tracks something reviewed on a real cadence, not a single number.
- You're tempted to list every KPI you could possibly measure — a board with thirty rows nobody actually reviews is worse than five that genuinely get discussed every cadence.

## How to fill it in

- **kpis** — Describe the function and what matters to it — a first-pass set of KPIs gets drafted, each with a monthly plan. Enter actuals yourself as each period actually closes; a real number is never invented.
- **coverage** — Computed for you from your KPIs, once actuals are entered — nothing to enter here.
- **abnormalities** — Log one whenever a period comes in red — a cause seen first-hand where the work happens and a 5-why root cause, not a guess.
- **countermeasures** — Every red gets at least a containment action (fast, protects delivery now) with an owner and a note on what's being done; add a permanent countermeasure (fixes the root cause) when the cause is understood.
- **narrative** — Drafted from the board actually built.

## Common mistakes

- **Letting a red pass with no response because it "looks like a one-off".** — Every red gets containment and a note on what's being done — that's how the board protects the customer while you learn more. Whether a miss is a one-off can't be judged from a single point or two in a row; it needs a run chart with enough history.
- **Treating two reds in a row as proof of a real change, or one red followed by a green as proof it was just noise.** — A couple of points can't separate ordinary ups and downs from a genuine shift. Judge trends on a run chart, and don't credit a countermeasure for a recovery until the run chart shows it holding.
- **Logging an abnormality's cause from a guess instead of direct gemba observation.** — A root cause written from speculation is usually wrong, and a countermeasure built on the wrong root cause doesn't actually fix anything — go and look before writing the cause down.
- **Tracking so many KPIs that none of them get real attention at the review cadence.** — The vital few discipline applies here the same as everywhere else in this catalogue — a shorter list that genuinely gets discussed beats a long one that gets skimmed.
