# Visibility board

The performance board discipline — the year-long view — pointed at a commercial function: bookings, pipeline quality, service velocity, team productivity. Plan vs. Actual phased across the year, computed red or green from real numbers, where every red gets containment and a note on what's being done, closing the loop into a gemba-grounded root-cause log and a countermeasure register. For a commercial team's week-by-week hit-or-miss board, that is the performance grid.

Family: Daily management · Format: .xlsx · Domain: commercial

## What it is

A visibility board is the performance board discipline pointed at a commercial function — bookings, pipeline quality, service velocity, team productivity — instead of a shop floor. Each key performance indicator (KPI) gets a real monthly plan and a computed status, never asserted. Every red gets a response, not just a color: containment (a quick action that protects the customer or the deal now) and a short note on the board saying what's being done and who owns it, then an abnormality log entry and a countermeasure with a real owner and a target date. The board also flags a KPI that has missed two or more periods running. Treat that as a prompt to check whether containment is holding, not as a test of whether the miss is a real change or ordinary ups and downs: two points in a row can't tell you that. To judge whether performance is genuinely shifting, plot the KPI on a run chart (its values in time order around a centre line) and look for a sustained pattern over enough points. The gemba — the place the work actually happens — in a commercial workflow isn't the shop floor: it's the customer relationship management (CRM) quote queue, the order intake portal, the enterprise resource planning (ERP) contract master, the pricing approval inbox. A real abnormality log entry comes from direct observation there, not speculation about what probably happened.

## When to use it

Use it when:

- A commercial function already has (or can name) the vital few KPIs that actually matter — bookings, quote quality, turnaround time, service level agreement (SLA) compliance — and wants an honest, computed record of how each is tracking.
- You want every red period to trigger a real response — containment now, a note on what's being done, and root-cause work in the actual commercial systems (the CRM, the ERP, the pricing engine) — not a status update nobody follows up on.
- You review the same commercial KPIs on a regular cadence and want the history kept, so trends can be judged on a run chart rather than argued about from memory.

Not when:

- You don't have a real plan or target for the KPI yet, just a hope it trends the right way — set a real plan first, or every period reads as an ungrounded pass/fail.
- You're tracking this KPI nowhere near its own review cadence — a board reviewed monthly needs monthly discipline behind it, not numbers nobody's actually checking.
- You're tempted to list every metric the CRM can report — the vital few discipline applies here too; a board with real ownership beats an exhaustive dashboard nobody discusses.

## How to fill it in

- **kpis** — Describe the commercial function and what matters to it — a first-pass KPI set gets drafted, each with a monthly plan. Enter actuals yourself as each period closes; a real reported number is never invented.
- **coverage** — Computed for you from your KPIs, once actuals are entered — nothing to enter here.
- **abnormalities** — Log one whenever a period comes in red — a real cause observed directly in the CRM quote queue, order intake, or wherever the work actually lives, not a guess.
- **countermeasures** — Every red gets at least a containment action (protects delivery now) with an owner and a note on what's being done; add a permanent countermeasure (fixes the root cause in the system or process) when the cause is understood.
- **narrative** — Drafted from the board actually built.

## Common mistakes

- **Letting a red pass with no response because it "looks like a one-off".** — Every red gets containment and a note on what's being done — that's how the board protects customers and deals while you learn more. Whether a miss is a one-off can't be judged from a single point or two in a row; it needs a run chart with enough history.
- **Treating two reds in a row as proof of a real change, or one red followed by a green as proof it was just noise.** — A couple of points can't separate ordinary ups and downs from a genuine shift. Judge trends on a run chart, and don't credit a countermeasure for a recovery until the run chart shows it holding.
- **Logging an abnormality's cause from a guess about the CRM or ERP instead of actually looking.** — A root cause written from speculation is usually wrong, and a fix built on the wrong root cause doesn't actually stop the recurrence — check the actual system before writing the cause down.
- **Treating a closed countermeasure as proof the KPI is fixed, without checking the KPI actually recovered.** — A countermeasure can close on schedule and still not hold — the honest signal is whether the KPI itself returns to green, not whether the action item got checked off.
