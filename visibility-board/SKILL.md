# Visibility board

A weekly scorecard for a sales or marketing team: target, actual and gap for each of the vital few measures, from the starting point through every week of the cycle, coloured red or green from real numbers, with an action and an owner for every red.

Family: Daily management · Format: .xlsx · Domain: commercial

## What it is

A visibility board is the performance board pointed at a commercial function (bookings, quote quality, turnaround, team productivity) and run weekly. For each of the vital few key performance indicators (KPIs) it keeps three rows across the weeks of a quarter: the target, the actual, and the gap between them, starting from the jump-off point (JOP), the last real measurement before the plan began, and ending in a quarter-to-date (QTD) column. Only the actual row is coloured: green met, red missed, blue for a week that closed with no number, white for weeks still to come. Weekly matters: a team that sees a miss only at month end has lost three weeks on the cause. Every red gets containment now, a line in the abnormality log with a cause seen first-hand in the system where the work happens (the customer relationship management (CRM) quote queue, the enterprise resource planning (ERP) credit records), and a countermeasure with an owner and a date. Two or more reds running is flagged as a prompt to check the containment is holding; whether performance is really shifting is judged on the run chart, not from two points.

## When to use it

Use it when:

- A commercial function already has (or can name) the vital few KPIs that actually matter — bookings, quote quality, turnaround time, service level agreement (SLA) compliance — and wants an honest, computed record of how each is tracking.
- You want every red period to trigger a real response — containment now, a note on what's being done, and root-cause work in the actual commercial systems (the CRM, the ERP, the pricing engine) — not a status update nobody follows up on.
- You review the same commercial KPIs on a regular cadence and want the history kept, so trends can be judged on a run chart rather than argued about from memory.

Not when:

- You don't have a real plan or target for the KPI yet, just a hope it trends the right way — set a real plan first, or every period reads as an ungrounded pass/fail.
- You're tracking this KPI nowhere near its own review cadence — a board reviewed monthly needs monthly discipline behind it, not numbers nobody's actually checking.
- You're tempted to list every metric the CRM can report — the vital few discipline applies here too; a board with real ownership beats an exhaustive dashboard nobody discusses.

## How to fill it in

- **kpis** — List the few KPIs that matter to this commercial function, each with a target for every period and a jump-off point (JOP): the last real measurement before the plan began. Enter each actual from the reported figures as the period closes, never an estimate. The Gap row is calculated — don't type it; it reads as the actual minus the target, so a minus sign means below target.
- **coverage** — Calculated from your KPIs once actuals are entered — don't type it; check it matches the reds and greens you can see on the board.
- **abnormalities** — Log one whenever a period comes in red: the cause you saw directly where the work lives — the CRM quote queue, incoming orders — not a guess.
- **countermeasures** — Give every red at least a containment action that protects delivery now, with an owner and a note on what's being done. Add a permanent countermeasure that fixes the root cause in the system or process once you understand it.
- **narrative** — Write a few sentences on what the board shows: which measures are off target, whether the gaps are closing, and which reds still have no permanent fix. Use only what the board records.

## What good looks like

The example below is Beacon Analytics' own commercial operations board: a thirteen-week quarter read at the end of week 9, so the last four weeks sit white. Quote first-pass yield has missed four weeks running: every red got containment and a log entry, and the credit sync fix closed on time and worked, but a second, unrelated failure mode kept it missing, so a second countermeasure is open. Commercial bookings had a single red week that got the same treatment — logged, root-caused and countermeasured — before it came back over plan. Nine weekly points are still few, so no trend is called; every measure stays on a run chart.

## Common mistakes

- **Letting a red pass with no response because it "looks like a one-off".** — Every red gets containment and a note on what's being done — that's how the board protects customers and deals while you learn more. Whether a miss is a one-off can't be judged from a single point or two in a row; it needs a run chart with enough history.
- **Treating two reds in a row as proof of a real change, or one red followed by a green as proof it was just noise.** — A couple of points can't separate ordinary ups and downs from a genuine shift. Judge trends on a run chart, and don't credit a countermeasure for a recovery until the run chart shows it holding.
- **Logging an abnormality's cause from a guess about the CRM or ERP instead of actually looking.** — A root cause written from speculation is usually wrong, and a fix built on the wrong root cause doesn't actually stop the recurrence — check the actual system before writing the cause down.
- **Treating a closed countermeasure as proof the KPI is fixed, without checking the KPI actually recovered.** — A countermeasure can close on schedule and still not hold — the honest signal is whether the KPI itself returns to green, not whether the action item got checked off.

## What it connects to

Upstream:

- **Performance grid** (`performance-grid`) — The board a commercial team marks period by period, asking only whether this one met its rule. This one keeps the whole cycle in view — target, actual and gap, week after week, against the point it started from. Different question, and worth keeping apart.
- **Sales funnel value stream map** (`sales-funnel-map`) — A flow-efficiency or conversion finding from the funnel VSM is exactly the kind of thing that turns into one of this board's own KPIs.
- **Key performance indicator (KPI) tree** (`kpi-tree`) — A KPI tree's driver decomposition is what earns a metric its place on this board in the first place — this tracks it over time, the tree explains why it matters.

Downstream:

- **Pipeline review cascade** (not in the catalogue yet) — This board's monthly review names what's off track; the daily/weekly tiered huddle cadence is where an abnormality actually gets worked between reviews.
